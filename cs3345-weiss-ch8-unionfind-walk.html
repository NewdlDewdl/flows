    Equivalence relations: reflexive, symmetric, transitive

    0:00–4:35YouTube app

    The whole video. A slide names the three properties (frame 1:10); ordinary equality is checked against each one, then equality of remainders mod 3: 10 and 7 are on the board at frame 3:30, and 13 comes in at 3:49 for transitivity. All three leave remainder 1. Same definition as the book, different examples.

    Key points

    • Chapter opener: one simple array and a few lines of code per routine give constant average time per operation, yet the analysis is very hard, and the worst case has a form not seen earlier in the book.
    • A relation R on a set S says, for every pair a, b in S, whether a R b is true or false.
    • Equivalence relation: reflexive (a R a for every a), symmetric (a R b exactly when b R a) and transitive (if a R b and b R c, then a R c).
    • ≤ is reflexive and transitive but not symmetric (2 ≤ 3, yet not 3 ≤ 2), so it is not an equivalence relation.
    • Equivalence relations in the book: electrical connectivity by wires, two cities in the same country, and towns reachable by road when every road is two-way.

    Check. Town a is related to town b when you can drive from a to b. If some roads are one-way, which of the three properties can fail, and why?

    Answer. Symmetry: a one-way road can take you from a to b with no way back from b to a. Reflexive (you are already there) and transitive (chain two drives) still hold, which is why the book asks for two-way roads.

    One failed property is enough to rule a relation out, as with ≤.

    • Trap. The examples differ: the video uses equality and remainders mod 3; the book uses ≤ (which fails), electrical connectivity, being in the same country, and towns reachable by road when every road is two-way (which all pass).
    • Trap. Letters: on the board the video labels its checks R: (reflexive) and S: (symmetric) (frame 3:30); in the book R is the relation and S the set it is defined on.

    Read in the book, not in the video: The chapter opener (what the structure costs and why its analysis is hard); what a relation is (for every pair a, b, the statement a R b is true or false); and the three properties as general rules: the video names them on a slide and shows them through examples. Also the book's four examples, above all ≤, the one that fails.

8.2 The Dynamic Equivalence Problem

  1. pdf354p.332

    The dynamic equivalence problem: find and union

    0:07–1:01YouTube app

    Disjoint Sets
    Mary Elaine Califf, plays 0:54 of 14:27

    The problem the structure solves: each item starts in its own set, union merges two sets, and find names the set an item is in. Items are numbered 0 to n - 1; an item's number is found in constant time, as in the book. The video's example relation is being in the same room.

    Key points

    • The task: decide quickly whether a ~ b when the relation arrives as a list of facts rather than a full table of pairs.
    • The equivalence class of a is everything related to a. The classes partition S: each element lies in exactly one.
    • Start with N one-element sets, all disjoint, so only the pairs a ~ a hold. find(x) returns the name of x's set; union replaces two sets by their union, so the sets stay disjoint.
    • To add a ~ b: find both; if the names differ, union them. Sets only ever merge, and that is what makes the problem dynamic.
    • Online (the book's case): each find is answered before the next operation is seen, like an oral exam. Off-line sees them all first, like a written exam, but each answer must still match the unions made before that find.
    • Finds and unions never compare element values; they only need to locate elements, so the book numbers them 0 to N - 1 (a hashing scheme can supply the number) and uses the numbers as array indices.

    Check. Facts: a1 ~ a2, a3 ~ a4, a5 ~ a1, a4 ~ a2. How many equivalence classes do a1 to a5 form?

    Answer. One. The first and third facts join a1, a2 and a5; the second joins a3 and a4; the fourth links a4 to a2, merging the two groups. All 25 pairs are related.

    Symmetry and transitivity fill in every pair nobody listed (a3 ~ a4, a4 ~ a2 and a2 ~ a1 chain a3 to a1), which is why the structure tracks classes, not pairs.

    Read in the book, not in the video: That a stored table of all pairs would answer a ~ b in constant time, but the relation usually arrives implicitly, as a few facts whose consequences must be worked out (the book's a1 to a5 example); equivalence classes and the partition they form; and online versus off-line algorithms.

    Quick-find and its cost; then sets as trees in an array

    Section 8.2/8.3

    1:01–1:54YouTube app

    Disjoint Sets
    Mary Elaine Califf, plays 0:53 of 14:27

    Section 8.3's structure: one array holds a forest, one tree per set. A root holds -1 and its index names the set; any other entry is the index of the item's parent. The stretch closes on the starting state for the video's ten items: the array all -1 and ten one-node trees (frame 1:50).

    Key points

    • Any name works for a set, provided find(a) == find(b) holds exactly when a and b are in one set.
    • Find and union cannot both run in constant worst-case time; this chapter keeps union cheap and works on find.
    • Quick-find: store each element's class name. find is O(1), union rescans the array, Θ(N); N - 1 unions cost Θ(N2).
    • With a linked list per class plus class sizes, relabel only the smaller class. An element's class at least doubles each time it is relabeled, so at most log N times: O(N log N) for N - 1 merges, O(M + N log N) with M finds.
    • Section 8.3: each set is a tree named by its root. Only parent links are needed, so the forest fits in an array: s[i] is the parent of i.

    Check. Quick-find's N - 1 unions cost Θ(N2) in total. When is that still acceptable, and why?

    Answer. When there are on the order of N2 finds or more: the union cost then spreads over so many O(1) finds that each operation averages O(1). With fewer finds it is too slow.

    A large total is fine when spread over enough operations; with few finds, quick-find's unions dominate.

    Read in the book, not in the video: Most of the page, everything before section 8.3: a set's name is arbitrary; find and union cannot both run in constant worst-case time; the applications (graph problems, and compilers handling equivalence or type declarations); and all of quick-find: an array of class names gives O(1) find, but union rescans the array, Θ(N), so N - 1 unions cost Θ(N2), and when that is still acceptable (see the check); a linked list per class alone does not change that; adding class sizes and relabeling only the smaller class gives O(N log N) for all the merges and O(M + N log N) overall. The chapter's target: only slightly above O(M + N). In 8.3, the trees need not be binary.

8.4 Smart Union Algorithms

  1. pdf360p.338

    Union by size stays cheap; union by height and its stored -(height) - 1

    10:26–11:20YouTube app

    Disjoint Sets
    Mary Elaine Califf, plays 0:54 of 14:27

    The rules of union by height: a root stores its height as a negative number (slide, frame 10:35); then, from 10:41 to 11:17, if heights differ the shorter tree goes under the taller and the height stays, and if they tie the second root goes under the first and the height grows by one.

    Key points

    • Union by size starts with every entry -1, gives the new root the sum of the two sizes, and needs no extra space.
    • It is fast on average too: under virtually all reasonable models, M operations take O(M), since random unions mostly merge small sets into large ones.
    • Union by height also keeps depth O(log N): put the shallower tree under the deeper one.
    • Height grows only when two equal-height trees join, and then by exactly one.
    • Roots store -(height) - 1, since a height of 0 must still read as negative. All entries start at -1.

    Check. Union by height. Two roots each store -3 (height 2) and are unioned: what does the new root store? And if they store -3 and -2?

    Answer. Equal heights: the new root stores -4 (height 3). -3 against -2: the height-1 tree goes under the height-2 root, which keeps -3.

    Only a tie raises the height. Fig 8.14 tests s[root2] < s[root1] because the more negative value is the deeper tree.

    • Trap. Height words: the video stores 'the actual height of the tree as a negative' (10:36), so a lone node (-1) counts as height 1; it counts levels. The book counts edges: a lone node has height 0 and stores -(0) - 1 = -1. Different words, same stored numbers: trust the numbers.

8.5 Path Compression

  1. pdf362p.340

    Path compression: every node on the find path points at the root

    0:09–1:21YouTube app

    Path Compression in Disjoint Sets
    Mary Elaine Califf, plays 1:12 of 4:53

    Trees can still grow tall under union by size or height (0:09-0:19), so find itself changes: every node it passes is made to point straight at the root. Example: find(4) in a tree rooted at 6 sends 4 and 5 (and 7, already there) to 6 (frame 1:00); after that their finds take one step.

    Key points

    • Smart unions are linear on average, but their O(M log N) worst case arises easily: put every set on a queue, then repeatedly dequeue two sets and enqueue their union.
    • Probably no union rule can do better: any rule can be forced into the same worst-case trees, because ties have to be broken arbitrarily. So, short of redesigning the structure, the speedup has to come from find.
    • Path compression: a find(x) relinks each node it passes on the climb so that its parent becomes the root. The step does not depend on which union rule built the tree (p. 341 adds the catch for stored heights).
    • Fig 8.15: find(14) on Fig 8.12's tree changes two links; 12 and 13 move up one level, 14 and 15 move up two.
    • Code change: s[x] = find(s[x]), so on the way back out of the recursion each node on the path is relinked to the root.
    • With arbitrary unions plus compression, M operations take O(M log N) in the worst case.

    Check. Arbitrary unions left the chain s = [-1,0,1,2,3] (4 under 3 under 2 under 1 under 0). What is s after one path-compressing find(4), and how many links changed?

    Answer. [-1,0,0,0,0]. Three links changed (s[4], s[3] and s[2]); s[1] already pointed at 0.

    Every node on the path now hangs off the root, so the next find on any of them takes one step.

    • Trap. The video's example tree (frame 1:00) has 5 nodes with 4 at depth 3. Neither smart union can build that: under either rule a node at depth d sits in a tree of at least 2d nodes (by size, p. 337's doubling argument; by height, a tree grows taller only when two equally tall trees join), so a 5-node tree is at most 2 deep. It is an arbitrary-union tree. The book shows compression on Fig 8.12's union-by-size worst case instead (Fig 8.15).

    Read in the book, not in the video: Why only find can be improved: the O(M log N) worst case of smart unions arises easily (sets on a queue, the front two dequeued and their union enqueued, over and over), and when finds far outnumber unions it is worse than quick-find; every union rule gives the same worst-case trees because ties must be broken arbitrarily. Also Fig 8.15, the one-line code change, the O(M log N) bound for arbitrary unions with compression, and why compression suits arbitrary unions: they leave many deep nodes for it to pull up.

    Key points

    • Fig 8.16 changes one line of Fig 8.9: the recursive result is stored in s[x] before it is returned (s[x] = find(s[x])).
    • Arbitrary unions with compression: M operations take O(M log N) in the worst case (a proven result the book reports); the average case is still open.
    • Compression works with union by size unchanged: relinking nodes inside a tree does not change its size.
    • With union by height, compression can make stored heights wrong. Do not recompute them: they become ranks (estimated heights). In theory union by rank has the same efficiency as union by size, and ranks change less often than sizes.
    • Whether compression pays on average, when union by size is already linear on average, is open; it does cut the worst case (section 8.6).
